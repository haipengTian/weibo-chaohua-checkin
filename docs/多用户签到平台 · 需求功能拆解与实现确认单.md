# 多用户签到平台 · 需求功能拆解与实现确认单

**需求来源**：用户对二开功能的描述及确认  
**适用项目**：haipengTian/weibo-chaohua-checkin  
**输出日期**：2026-11-17  
**当前状态**：用户于 2026-11-17 确认「开始吧」；首版本地实现与隔离测试完成，真实微博验收和远端发布待部署阶段执行

## 1. 需求背景

将当前一个面板账号管理全部微博账号的工具，改为多用户签到平台。

- 普通用户：注册、登录平台，扫码绑定自己的微博，选择每天几点自动签到。
- 管理员：查看用户列表、执行日志、统计和异常，负责运行监控。
- 两种账号独立：平台账号识别用户身份，微博账号提供签到登录状态。
- 已有 Fork、本地源码和服务器部署保留；本阶段不更改线上服务。

## 2. 本次实现范围

### 2.1 已确认的功能方向

- 用户端与管理端分开，建议独立网页入口、共用后端。
- 用户端支持注册、登录、微博扫码绑定、每日定时设置、开启或暂停签到。
- 用户查看自己的签到结果与微博登录状态，失效后重新扫码。
- 管理端提供用户列表、统计概览、异常监控、执行日志筛选。
- 用户之间的数据隔离；管理端查看运行信息，不展示 Cookie 等凭据。
- 用户自行选择的是每天的一个时间点，例如 `08:30`，不是每周哪几天；按北京时间执行。
- 一个平台用户可以绑定多个微博账号；每个微博账号只能归属一个平台用户。
- 用户端、管理端以及注册登录页面采用本地 `credit-ui` 风格，来源为 `E:/workspace/personal/ai/credit-ui`，不是另行设计一套相似皮肤。

### 2.2 当前未纳入的功能

付费套餐、原生手机 App、永久免验证自动登录均没有提出，不纳入本稿。管理员修改用户签到配置、代用户操作微博、禁用用户等写操作未定义，管理端首轮按统计监控设计。

### 2.3 首版实现选择

- 新平台使用用户入口 `/`、管理入口 `/admin`，共用 FastAPI 后端；计划在部署阶段接入 `wb.thpvip.xyz`。
- 注册先采用用户名、密码；离线管理员命令支持密码恢复并撤销会话，邮件或短信验证、自助找回另行梳理。
- 每位用户一份每日计划，对其绑定的多个微博账号生效；是否需要逐微博设置不同时间尚未提出。
- 沿用微博扫码和签到核心逻辑，不重写一套微博接口。

## 3. 功能点拆解

| 编号 | 功能点 | 类型 | 优先级 | 验收标准 |
|---|---|---|---|---|
| F001 | 平台注册、登录、退出 | 页面/接口 | P0 | 新用户注册后可登录；重复注册及错误密码有明确提示；退出后旧会话不能继续访问 |
| F002 | 用户多微博扫码绑定 | 页面/权限 | P0 | 同一用户可添加多个不同 UID 的微博；二维码仅归发起用户；已有他人归属的 UID 不能被绑定或覆盖；同一用户重新扫码更新原绑定而不新增重复账号 |
| F003 | 每日签到计划 | 页面/任务 | P0 | 用户设为每天 08:30 后，服务按北京时间执行；修改计划不影响其他用户；暂停后不再自动执行 |
| F004 | 个人签到状态 | 页面/接口 | P0 | 展示本人微博、最近结果和登录状态；失败与登录失效分别显示；看不到他人账号 |
| F005 | 管理端用户列表 | 页面/权限 | P0 | 管理员可分页查看平台用户及关联微博数量；普通用户访问被拒绝 |
| F006 | 统计概览及异常监控 | 页面/接口 | P0 | 时间范围内的执行统计与明细一致；登录过期、网络故障、签到失败可分别定位 |
| F007 | 日志查询 | 页面/接口 | P0 | 管理员按用户、微博账号、时间、结果筛选分页；日志不含密码、Cookie、二维码换票凭据 |
| F008 | 用户数据和角色隔离 | 权限/存储 | P0 | 所有查询及修改由后端校验身份与归属；更换资源 ID 不能越权；注册不能自选管理员角色 |
| F009 | 登录维护、失效通知 | 状态流/通知 | P1 候选 | 继承前期讨论方向；通知配置归属、渠道和交付范围另行确认 |
| F010 | credit-ui 视觉与交互 | 页面 | P0 | 用户端、管理端及注册登录页面统一沿用 credit-ui 的布局、主题、卡片、表格、弹窗和反馈方式；桌面及手机主流程可完成，不带入演示业务数据 |

## 4. 页面与交互

| 页面 | 内容 | 权限 |
|---|---|---|
| 用户注册/登录 | 平台账号表单、错误反馈、提交中状态 | 未登录可访问 |
| 用户工作台 | 本人微博绑定、扫码弹窗、每日计划、启停、最近结果 | 已登录普通用户 |
| 管理登录与后台 | 概览、用户列表、异常、日志及筛选 | 管理员 |

用户端不展示全站日志、其他用户和管理统计。空账号时引导扫码绑定；二维码过期可重新获取；请求失败恢复按钮。后台按用户和微博账号分别标识，避免混淆平台用户数与绑定账号数。

### credit-ui 风格来源与应用

已只读检查 `E:/workspace/personal/ai/credit-ui/README.md`、`NOTICE.md`、`app/globals.css`、`app/(main)/layout.tsx`、`components/layout/sidebar.tsx`、`components.json` 及现有组件目录。

- 结构：沿用侧栏、60px 顶栏、可收放内容区域和自适应间距。用户端突出微博账号及签到操作；管理端突出指标、异常和查询表格。
- 样式：沿用现有主题变量、字体层级、圆角、边框和明暗主题基础，不擅自替换为新配色。首版使用现有默认设计变量，支持浅色和深色。
- 组件：输入、搜索、筛选下拉、日期选择和时间选择使用 credit-ui 实际组件；同时复用 Button、Label、Switch、Tabs。日期用 Calendar + Popover，时间用 Popover + 小时/分钟 Select 组合。保留原页面的表格与扫码交互，不增加无关 Dock、排行榜或大幅装饰。
- 业务：保留本项目的微博签到信息层级，不复制 Credit 积分、余额、支付或本地演示数据；身份验证和数据隔离由本项目服务端实现。
- 来源：credit-ui 是基于 Credit（Apache-2.0）和 CDK（MIT）的本地 Starter。本项目按需复用 Credit 组件，保留对应许可与修改说明；React 局部挂载接入现有页面，Vite 仅生成静态文件，不引入 Next.js 部署链。来源与许可见根目录 NOTICE.md。

## 5. 接口契约

以下是新 `portal:app` 入口的接口约束；旧 `app:app` 保留原有接口与调用方式。

| 功能 | 拟定接口范围 | 契约要求 |
|---|---|---|
| 平台认证 | `/api/auth/*` | 注册不接受角色或归属字段；登录返回安全会话，不返回密码散列 |
| 个人微博、扫码及计划 | 沿用并调整现有 `/api/accounts/*`、`/api/login/qrcode*`、`/api/settings` | 所有资源按当前平台用户过滤，二维码会话也绑定所有者；跨用户绑定同一 UID 时返回绑定冲突，不返回原所有者身份 |
| 管理查询 | 新增 `/api/admin/*`，以 GET 查询为主 | 后端强制管理员权限，支持分页筛选，不返回微博登录凭据 |
| 个人统计、日志 | 现有 `/api/stats`、`/api/logs` 的职责需拆分 | 不能将现有全站数据直接暴露给普通用户 |

新旧服务使用独立入口和数据目录。旧账号通过显式迁移命令归指定管理员，保留账号 ID、原 JSON 和备份；不让新注册用户取得旧数据。实际使用与升级步骤见《多用户平台使用与升级.md》。

## 6. 字段、枚举与状态

核心字段建议：平台用户 `id/username/password_hash/role/created_at`；微博绑定 `id/owner_id/uid/nickname/login_status`；计划 `owner_id/enabled/time/timezone`；执行记录 `user_id/account_id/trigger/started_at/finished_at/result`。

- 平台角色：普通用户、管理员；角色由服务端维护。
- 微博 `uid` 是归属识别依据，不以昵称去重；同一个 UID 在全平台只能有一条有效绑定关系。
- 微博登录状态：有效、失效、检测异常。网络请求失败不能直接判为登录失效；检测恢复后可返回有效。
- 执行结果：成功、部分失败、失败；超话数量为 0 不直接计作签到成功。
- 记录成功、已签到和失败的超话数量，保留触发方式及可读异常摘要。
- 统计分别说明用户数、账号执行次数、超话次数；首页需区分今日与所选时间范围。

## 7. 权限、租户与数据边界

- 以平台用户为数据隔离边界，不另引入企业租户概念。
- 用户只能访问和操作自己的绑定、扫码会话、计划和结果；不信任前端传入的 `owner_id/user_id`。
- 跨用户扫码不能替换原绑定的所有者或 Cookie；并发扫码也必须维持 UID 唯一归属。账号转移需独立规则，不通过再次扫码隐式转移。
- 管理员可跨用户查询运行信息，首轮不包含代签、导出 Cookie 或读取微博密码。
- 用户密码只保存安全散列；微博凭据仅供服务端执行任务使用，不进入网页响应或日志。
- 注册、登录、扫码绑定和计划变更需有可追踪记录，不记录敏感参数。

## 8. 校验、异常与国际化

- 注册名大小写不区分且唯一；用户名 3–32 位字母、数字、中文、下划线、点或短横线；密码 12–128 位。
- 微博已归属其他用户时提示「该微博账号已被绑定」，不透露对方用户名；同用户重新扫码则更新本人的登录状态。
- 每日时间为有效 `HH:mm`，`00:00` 至 `23:59`；非法值前后端均拒绝。
- 匿名访问返回 401；已登录但无管理权限返回 403；跨用户资源按统一策略隐藏或拒绝。
- 登录/注册需要限制尝试频率；扫码过期、微博要求验证、网络失败、签到接口失败分别提示。
- 提示文案、按钮、状态及统计单位先沿用简体中文；多语言尚未要求，不新增语言切换。
- 本轮无上传下载或导入导出功能。

## 10. 测试与验收场景

每个 P0 功能点（F001–F008、F010）的表内标准作为必测主路径，另覆盖：

- 两个普通用户和管理员同时使用：扫码归属、账号列表、任务计划、日志查询均不串数据。
- 一个用户绑定多个微博后均能展示、检测和签到；同用户重扫码不重复新增；跨用户及并发绑定同一 UID 均不覆盖原归属或凭据。
- 新用户无绑定账号、无执行记录时，显示空状态，不生成虚假统计。
- 重复提交、二维码过期、密码错误、时间非法、会话过期和越权访问均有确定反馈。
- 不同用户设置不同时间，修改、暂停及服务重启后仍按各自配置运行；同一任务不重复执行。
- 微博登录过期与网络超时分别落状态和日志；统计汇总能对上筛选后的明细。
- 历史账号及设置迁移后可继续使用；迁移失败保留原数据，可恢复旧版本。
- 用户端、管理端在电脑和手机实际操作；当前中文文案、时间单位和状态显示一致。
- 对照 credit-ui 实际渲染验收布局、主题、表格密度、弹窗及加载/空/失败状态；窄屏无页面级横向溢出，扫码和时间设置可操作。
- 真实扫码和签到在用户授权账号上验收；发布、远端迁移和重启另获授权后执行。

## 11. 风险与待确认项

| 事项 | 影响 | 当前建议 |
|---|---|---|
| 微博解绑或转移后的归属规则 | 影响后续重新绑定和历史数据保留 | 已确认每个微博只归属一个平台用户；跨用户扫码不自动转移。解绑及转移的操作入口和历史保留规则后续梳理 |
| 注册验证和找回密码 | 影响公网开放及用户自助恢复 | 首版已采用用户名密码注册和离线恢复；邮件验证、自助找回留待后续 |
| 管理员账号和旧数据归属 | 影响现有服务升级 | 原面板所有者保留管理员身份，旧微博归该账号；迁移前核对 |
| 通知配置与登录维护 | 影响个人令牌隔离和二开范围 | 通知按用户隔离，不复用他人通知配置；具体渠道另定 |
| 服务停机、失败后的补签 | 影响签到完整性与统计 | 首版仅补当天，自动失败重试从上次结束计时、间隔 10 分钟，每账号每天最多 3 次自动尝试；跨日终止旧任务 |
| 日志保留期限和异常口径 | 影响存储及监控效果 | 首版保留全部结构化记录，不自动删除；执行为账号任务次数，新签超话为成功次数累计，快照与范围统计分开展示 |
